## 平台范围

- 网关与工作进程统一通过 Unix 域套接字通信。开发套接字位于当前用户的私有目录，生产套接字沿用服务组权限。工作进程在初始化原生运行时前取得独占锁，关闭服务和原生进程后释放，进程异常退出时由内核释放。真实进程竞争测试分别覆盖同时启动和异常退出后同时恢复。
- 项目自己的进程管理、路径处理、客户端连接、测试入口和 CI 均按 macOS、Linux 的运行约定实现。macOS 增设开发验证作业，Linux 分普通账号和 root 验收。
- 固定版本的上游数据保留原始平台名称。Codex CLI 在 Unix 上返回的通用配置 Schema 引用五个带其他平台名称的定义。pnpm 标准锁文件保留六个相关的第三方可选包，Go 的传递依赖校验和也保留模块原名。项目通过这些记录核对官方协议和依赖完整性。
- 历史审计、旧版下载和测试证据按原提交保留。修正了六处历史证据引用和旧版 Python 无法验证归档的问题。默认 Python 3.10 验证通过全部 874 条历史记录。[历史材料取回方法](../history/README.md)

两轮的官方 MCP 公开核验分别取得六份 HTTP 200 响应。依赖树另经 pnpm 完整扫描，当时各严重等级的登记数均为零，未使用豁免。发布前的 Git 历史扫描只保留已逐项复核的历史合成样例，当前源码及新材料没有未处理匹配。

在随后的 ARM64 全量验证中，375 个 root 用例全部通过。普通账号的 JavaScript 测试有两项在磁盘并发压力下失败。对同一份代码单独复测，WAL 导出和工作区互斥的功能断言均通过。测试夹具另有两个可独立复现的问题。

- WAL 测试为准备 420 条真实落盘回执耗尽了快照导出的 15 秒用例时限。现在给准备阶段独立的 60 秒时限，仍以原来的 15 秒验证并发写入、420 条回执、摘要和导出完整性。单独延迟准备至 17.5 秒时，导出验证用时约 0.25 秒，通过全部断言。
- 工作区互斥测试靠短时轮询猜测助手是否已经接单，轮询先超时还可能卡住清理。改为等待助手实际接单或操作返回，遇到断言失败也会释放等待的操作。把接单人为延迟 1.75 秒可以稳定复现旧问题，修正后并发和排他断言均通过。

这两项修正只涉及两个测试文件。最终审计和全量测试再次从新的源码摘要开始。
