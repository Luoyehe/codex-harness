# Reviewed checks 历史复盘

历次失败的日志定位、版本归属、受影响入口、回归和未完成验证都保存在原提交。[完整历史复盘](https://github.com/Luoyehe/codex-harness/blob/b2f5a1f798e9fb26ba40eb79d8bb63ab93ca8052/verification/reports/reviewed-checks-history.md)

后续提交需要延续以下核验工作。

- 观察完整作业结果，包括预备工具失败、取消、跳过、真正执行的用例和代码覆盖范围。重新执行成功并不能解释第一次失败。
- 离线账本、降权读取和服务重启等修复，在 Linux 上分别使用普通用户和真实 root 测试，并包含实际部署所使用的文件、目录和配置组合。
- 原生协议或共享数据结构有改动时，一并检查浏览器、网关、运行时和部署消费者。单个夹具通过不足以覆盖它们之间的约定。
- 验证应绑定准确的 Git 提交、源码摘要、固定工具链及授权范围。合并队列须对其实际候选提交做检查。旧版证据不授权当前源码。
- 以隔离 HOME 和本地对端测试。公网服务、生产账号和手机真机只记录实际完成的验证。
