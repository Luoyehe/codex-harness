## 验收边界

- 手机端区分自动化交互、真实浏览器事件和用户先前报告的真机现象。本文没有把模拟测试计作一次新的手机 Edge 真机验收。
- 使用官方 Codex CLI 核对 479 个 JSON 与 951 个 TypeScript 协议生成文件。以公开资料核验智谱四个内置服务，实际工具传输走隔离的本地环境。外部商业服务的成功率、会员权限与当时偶发失败的唯一根因仍无法从这些测试推定。
- 原生传输每帧最多 12 MiB。单条非图片消息已经超过此值且独立时间线也不能返回可用游标时，应用仍须遵守这条传输边界。
- 隔离 Debian 的用户、项目、自动化、回执与系统服务用于升级验证。发布到 GitHub 与升级用户线上实例是两个独立动作。

## Debian 的实际升级结果

专用 Debian 12 实例上先从原版 v2.4.0 运行真实应用，完成管理员登录，建立浏览器 WebSocket，创建项目与暂停的自动化，记录两条已接受的操作回执。旧控制程序因服务启动问题需要先升级，建立业务基线时复用了经原版校验并封存的 v2.4.0 应用包。

随后使用正式管理入口依次完成控制工具升级、配置迁移、HTTPS 配置核对、应用升级和安装验证。升级后原浏览器 cookie 仍有效，原管理员可重新登录，WebSocket 可用，能按原 ID 读取项目与暂停的自动化，两条回执仍为 accepted。SQLite 完整性检查通过，运行表由 16 列迁为 17 列。随后对 17 列账本执行正常停服恢复并重启，再次确认原 cookie、项目、自动化和两条已接受回执均有效。独立 Linux root 控制工具和账本恢复定向测试 76 项全部通过。另一次更新实际安装了长会话修复，用 10,073,992 字符输入得到 988,500 字符的展示窗口，最新最终答复保留。[升级证据](../audit-evidence/v250-platform/debian-upgrade.json)

第六轮在修订排序后覆盖 2,182 个文件，执行 172 个定向用例、1,200 组排序比较，重建并比对 1,430 份官方协议文件，未发现新增需修问题。[第六轮独立记录](../audit-evidence/v250-round6/independent.json)

第七轮核对同份源码，在两个真实的智谱配置管理流程中分别复现 P2 缺陷。第一项是连接切换后，服务显示名称从带连接后缀变成无后缀，原本属于同一连接的强制启用、停用均失效。第二项是永久删除连接后，其开关仍占据 128 项存储额度。顺次创建并删除 32 条各有四项开关的连接后，新连接显示没有覆盖设置，用户却无法再保存第一个开关。两项均能通过本地正式入口重现。外部智谱调用并非触发条件，本次复现也无法推断此前某次服务调用失败的原因。[第七轮独立记录](../audit-evidence/v250-round7/independent.json) · [连接切换](../audit-evidence/v250-round7/provider-switch.json) · [额度耗尽](../audit-evidence/v250-round7/removed-provider-capacity.json)

## 第九轮和原配置的连续启动验收

两种合法的 TOML 写法触发同一项启动缺陷。一种用点号键为服务赋内联表，另一种在表头的双引号名称内使用 Unicode 转义。Python 可以把两种写法解析成正确的服务和开关值。旧迁移代码仍按文本拼写查找待删除的设置，写入待确认区后无法移除原设置，后续启动反复失败。

Debian 启动对照复用了两种故障写法，以普通服务身份和 root 分别在同一用户目录连续启动两次。这里使用的模型名为 `fixture`；首次审计记录的模型名为 `test-model`，转义表头样本的赋值空格也不同。修复前异常写法的八次启动全部失败，规范表头的四次对照成功。修复后十二次均收到官方 Codex CLI 0.169.0 的初始化响应。原模型设置保留，旧开关保存在待确认区，没有指向其他连接；每组第二次启动前后两份持久文件的内容、inode、权限和修改时间均一致。另对点号键、引号、内联表及相邻字段的 216 种组合做了定向验证。[原配置](../audit-evidence/v250-round9/original-config-retries.json) · [实际启动记录](../audit-evidence/v250-platform/toml-startup.json)

随后在已安装的 `historical-commit-023` 上直接提取首次审计 JSON 两个 input 字段的 UTF-8 字节，分别为 66 和 67 字节，保留原模型名及原有空格。以真实普通服务身份和 root 分别使用同一目录连续启动两次，8 次均收到固定 CLI 的初始化响应，未发起模型回合。模型仍为 `test-model`，未归属开关仍为 false，第二次启动未再次改写文件。[首次审计原文逐字节重放](../audit-evidence/v250-platform/original-r9-historical-commit-023.json)

## 第十轮复审
