## 集成测试额外发现

- Linux 临时文件系统上，相同长度的原地改写可能保留相同时间戳。历史附件检查点恢复时增加已解析前缀的流式摘要核对，旧文件引用能正确作废。强制元数据相同的改写场景连续 30 次通过。
- 同样的时间戳碰撞也能使正在验证密码的请求漏掉离线账号重置。现在每次授权核对有大小上限的引导文件内容，内容相同时复用解析结果。已验证重置期间不能签发旧会话。
- 指南的示例测试文件 `tests/deploy/test_workspace_git.py` 在当前仓库不存在。实际执行了仓库内的 `test_workspace_index.py`、`test_workspace_commit.py` 和工作树测试。

三项跳过均为 Windows 专属语义，分别是文件占用时的真实删除拒绝、Windows 进程身份查询和扩展驱动器路径。仓库测试器会把包含跳过的组标记为 `skipped`。桌面 Edge 已实测首屏和配色，触屏焦点经过交互回归，手机 Edge 的系统软键盘尚未在真机重测。CI 合并队列通过本地 Git 事件和授权校验用例验证。

在 Node 24.22.1、pnpm 11.22.0 下，服务端、网页端、测试代码三套类型检查及生产构建通过。构建有现存的大分块体积提示。源码快照为 2,195 个文件，SHA-256 为 `43c43cbb49785c7543f7969ee96966383850d2f247cc28cd57fc063ff1825006`。源码扫描无发现，Git 历史核对保留 32 条既有的已复核样例匹配，新增未复核发现为零。

## 已运行 v2.5.0 的实例

M01 有一项历史数据边界。升级后，新操作及留有完整可信成功见证的旧操作可以正确确认。若旧版已把文件写回，却在保存可信成功见证之前就报错，单靠文件存在或原生恢复目录无法证明是该次写入所致。原操作应保留为结果未知，由管理员核对目标内容和原回执，避免重复恢复覆盖后续改动。
