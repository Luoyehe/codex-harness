# 用户工作流程修复记录

本轮从已发布的 v2.1.1 出发，按用户实际使用反馈修复功能和界面。开发阶段只做受影响模块的定向测试、必要的类型与构建检查；随后按用户最新要求完成一轮无新增问题的完整审计，再进入全量测试和发布验收。各阶段的实际结果见执行记录，历史测试不替代当前版本的验收。

## 修复范围

| 用户反馈 | 修改 |
| --- | --- |
| 设置菜单和模型账号分散 | 账号登录合并到对应供应商卡片；项目目录、本地草稿、账号安全、操作记录分别有明确入口 |
| 智谱未填默认模型保存失败 | API 凭据和可选默认模型分开保存；默认模型允许为空 |
| 模型和思考强度无法刷新 | 智谱使用注明来源的官方兼容目录；自定义 Responses 从实际目录获取；保留能力来源和人工配置入口 |
| 无供应商或未登录仍显示预填模型 | 按已启用供应商及登录状态生成菜单；不把原生捆绑目录冒充可用账号目录 |
| 只能启用一个供应商 | 独立连接、凭据、目录与新会话默认供应商；按会话路由，同名模型用供应商身份区分 |
| 两步验证入口不明显 | 身份确认和启用步骤放在可见卡片；密码修改折叠；保持真实 TOTP、恢复码及设备撤销流程 |
| 输入区混乱、模型和思考强度分离 | 同一模型弹层选择模型与思考强度；高级输入收进对话设置；保留运行中的追加/排队与停止操作 |
| 用量展开破坏布局 | 有边界的用量弹层，按最近一轮/累计展示指标；桌面与手机验证 |
| 成功回执持续提示 | 对话只提醒需处理的状态；操作记录可查看完整保留项；仅已消费的成功记录可在容量压力下回收 |
| 会话组织名称晦涩 | 改为会话分组与历史管理，明确归类不会移动文件 |
| 云 CLI 退出后后台锁死 | 启动前确认 ChatGPT 登录；已确认退出转入自动刷新，而不是永久未知；HTTP 回执送达后重建后台连接 |
| 无法添加项目 | 默认可创建由执行账号持有的新目录；已有目录注册区分不存在、不可进入和非目录 |
| 运维步骤过多 | 根目录统一菜单覆盖安装、升级、HTTPS、状态、日志、恢复和管理员用户名/密码重置 |

多供应商联动额外覆盖：旧会话供应商别名、目录代次替换后的继续会话、同名模型分页、局部目录失败提示、失效思考强度，以及默认模型读取期间不得使用旧值发送。

## 已执行的检查

- 浏览器：真实构建产物的模型/思考强度弹层、折叠输入区、账号安全卡片、用量弹层；桌面与 360 像素手机宽度。视觉页面使用显式标记的只读夹具，不代表真实模型输出。
- 网页和网关：设置导航、设备码恢复、模型选择、默认值读取、输入与附件、回执存储及容量、真实 HTTP 的 TOTP 启用/确认/登录/恢复码/关闭。
- 原生 CLI 0.164.0：真实子进程、PTY、网关和 WebSocket；本地协议服务验证两个供应商的同名模型分别路由，以及目录代次替换后继续会话仍使用正确供应商与思考强度。
- 120 隔离实例：真实 Linux 执行身份创建目录；终端关闭回执送达后 systemd 自动重启，并可再次创建会话。现网实例未作为测试夹具。
- 统一菜单：真实 Linux Shell/TTY 入口、兼容旧入口及不联网的 DNS 配置规划；部署管理逻辑另有定向测试。

未在本轮调用付费模型、真实外部 MCP、消耗账号额度或修改用户两步验证；本地协议服务不证明供应商商业权益或外部业务成功。最终部署状态及补充检查见执行记录，本文件不单独宣称已经上线或发布。
