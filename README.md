# Codex Harness

**把 Codex 放在自己的服务器上，在浏览器里完成开发工作。**

用电脑或手机管理项目、继续对话、审批操作、查看代码修改和使用终端。项目、配置和会话保存在服务器上，关闭网页后可以回来继续。

当前版本 **2.2.0**，适配 **Codex CLI 0.164.0**。适合个人自托管：一个管理员账号管理整个工作台，不提供不同用户之间的数据隔离。

## 能做什么

- **从对话到代码**：选择模型和执行权限，发送文件、图片或音频，查看计划、工具执行结果与代码修改。
- **管理多个项目**：浏览和编辑文件，搜索代码，查看 Git 状态、提交修改，以及管理独立工作区。
- **处理长任务**：继续历史会话，安排待执行消息、目标、子 Agent 和定时任务。
- **连接常用工具**：管理技能、插件、MCP 和模型供应商配置，也可以打开服务器终端。
- **内置账号登录**：用户名和密码即可进入；支持两步验证、恢复码和登录设备撤销，无需 Authelia。
- **断线后有据可查**：保留草稿并核对操作结果，避免因网络中断重复提交任务。

## 部署

准备一台 **Ubuntu 24.04 或 Debian 12** 服务器（x64 / arm64、systemd），确保能访问源码下载站点和你的模型服务。登录服务器，在管理员终端运行以下命令；普通用户先运行 `sudo -i`：

```sh
apt-get update
apt-get install -y git python3
git clone https://github.com/Luoyehe/codex-harness.git /root/codex-harness
cd /root/codex-harness
sh ./harness.sh
```

这是部署和日常维护的统一入口。选择 **“安装新实例”**，按提示填写实例名称、管理员用户名和密码，再配置域名与 HTTPS。脚本会安装缺少的系统依赖，准备固定版本的运行时、构建应用、注册并启动服务；**不需要自己安装 Node.js / Codex CLI、打包源码、编写 systemd 文件或生成管理令牌。** 模型账号进入网页后再设置。

公网访问需要你准备：

- **域名和解析**：把域名指向服务器的公网入口。
- **访问端口**：菜单默认使用 `18443`，可以改成 `10000` 等端口；在防火墙或路由器放通并转发对应 TCP 端口。
- **证书验证方式**：公网 80 或 443 能转发到服务器时，选择普通自动验证；两者都被运营商封锁时，选择 DNS 自动验证。

DNS 自动验证支持 **阿里云、腾讯云 DNSPod、Cloudflare、华为云、Amazon Route 53 和 DigitalOcean**。选择域名的实际 DNS 托管平台后，菜单会提示所需的专用 API 凭证，支持隐藏输入或读取已有文件，**不必手写 JSON**。凭证需要域名的 DNS 记录管理权限；签发和续期由 Caddy 自动处理，保持服务和凭证有效即可。权限准备详见 [DNS 凭证说明](deploy/README.md#dns-credentials)。

普通自动验证虽然允许网页使用高端口，但证书签发仍需公网 TCP **80 → 本机 18081**，或公网 TCP **443 → 本机 HTTPS 端口**（TLS 透传），至少满足一项。菜单会根据选择展示具体要求；它不能代替路由器转发、运营商解封端口或授予 DNS API 权限。

完成后打开菜单给出的 **`https://你的域名:端口`**，检查浏览器证书并登录。暂时没有域名，可跳过 HTTPS；菜单会给出 SSH 隧道命令和临时访问地址。使用 Cloudflare 的默认高端口入口时，请将记录设为 **DNS only（灰云）**。

以后在同一源码目录运行 `sh ./harness.sh`，即可升级、配置证书、查看状态和日志、重启服务、恢复中断的操作或重置管理员账号。升级前先在这个独立源码目录取得并检查新版本，再选“升级当前实例”；脚本会按顺序更新控制工具、配置层和应用，保留账号、项目和证书数据。已有命令行参数继续可用，自动化和特殊网络配置见 [部署指南](deploy/README.md)。

## 开始使用

1. **添加模型供应商**：打开“设置 → 模型供应商”，填写服务配置，或在同一页面完成 ChatGPT 登录。可以同时启用多个供应商，并指定新会话的默认供应商。
2. **添加项目**：选择“新建项目”，输入名称即可创建可用目录；已有代码则选择“添加已有目录”，填写服务器上的绝对路径。已有目录需要允许执行账号访问，不会自动上传电脑文件或修改目录权限。
3. **开始对话**：点击“新会话”，输入任务并发送。在输入框底部的模型菜单里一起选择模型和思考强度；文件引用、执行环境、审批和沙箱选项收在“对话设置”中。

| 模型源 | 需要准备什么 |
| --- | --- |
| ChatGPT / Codex 账号 | 可使用 Codex 的账号，在网页完成设备码登录 |
| 国内智谱 Coding Plan | Coding Plan API Key；默认模型可留空，保存后读取官方模型目录 |
| 自定义 OpenAI 兼容服务 | 服务地址及服务要求的 Key；必须支持 **Responses API**，模型从服务目录获取，也可手动配置 |
| ChatGPT 企业网关 | Codex 兼容网关地址及 OAuth 配置 |
| Amazon Bedrock Runtime / Mantle | 支持区域、Bearer API Key 和模型权限 |

模型菜单按供应商分组，未配置或未登录的服务不会预填一组模型。思考强度只显示目录中已知的选项；智谱使用官方兼容目录，自定义服务提供的能力信息不足时可手动补充。目录并不保证账号已获得全部模型权限。模型调用、语音及外部 MCP 可能消耗相应服务额度。

默认 **Enter 发送，Shift + Enter 换行**，可在“设置 → 通用”修改。文件、Git 和会话工具用于查看修改、继续或分支会话；“会话分组与历史管理”用于整理会话分类，不移动项目文件；“自动化”用于管理定时任务。完整能力与限制见 [功能清单](FEATURES.md)。

## 日常管理

在“设置 → 账号与安全”修改密码、管理登录设备或启用验证器两步验证。启用时先验证当前密码，将页面提供的密钥加入验证器，再输入六位验证码确认，并保存恢复码。工作台账号与模型供应商账号分别管理。

忘记密码或需要更改管理员用户名时，在服务器源码目录运行 `sudo sh ./harness.sh`，选择 **“重置管理员用户名和密码”**。菜单会提示输入新用户名与密码，并说明两步验证和已有登录会被清除。若网关暂时不可用，重置信息会保留，菜单会明确提示先恢复服务再登录。正常服务重启会保留尚未过期的登录会话。

服务状态、日志和模型配置可在网页设置中查看。正常完成的操作不会一直弹出提示；失败或结果待确认的操作会显示处理入口，完整记录可在“设置 → 操作记录”查看。**更新请使用部署工具，不要在运行目录直接 `git pull`，也不要单独升级 Codex CLI。** 从旧版升级、迁移 Authelia、备份与故障恢复请按 [部署指南](deploy/README.md) 操作。

HTTPS 异常时，打开管理菜单的“状态与诊断”和“查看日志 → HTTPS”；服务运行不代表证书已签发成功。菜单的“修复 / 恢复 / 回滚”按中断阶段提供恢复入口，不会自动重复提交失败操作。

安装中断、卸载后恢复服务、离线备份和候选目录归档见[恢复与维护](deploy/RECOVERY.md)。这些操作会保留原账号和数据；不要重新安装同名实例来覆盖失败现场。

## 使用时需要知道

- 这是单管理员工作台，登录者共享项目、模型账号和执行权限。项目列表用于选择目录，不代表用户之间的安全隔离。
- 关闭网页通常不会停止模型任务；网页终端会随连接断开而清理，不能用于托管长期服务。
- 出现“结果未知”时，先检查历史与服务状态。系统不会自动重发已经提交但未确认的操作。
- 未发送的草稿和本地恢复记录保存在当前浏览器、当前访问地址下，不会跨设备同步。清除站点数据或更换域名、端口前，请先保存草稿并核对未确认的操作。
- 密码、恢复码、模型 Key 和包含凭据的备份应妥善保存，不要提交到 Git 或交给任务中的 Agent。
