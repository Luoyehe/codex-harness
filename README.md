# Codex Harness

在自己的 Linux 服务器运行 Codex，用浏览器管理项目、继续对话、审批操作、查看修改和使用终端。电脑与手机都可以访问；项目、配置和会话保存在服务器上。

这是**单管理员自托管工具**。登录者共享项目、模型账号和执行权限，不提供多人之间的数据隔离。

版本 **2.0.0**，使用固定的 **Codex CLI 0.164.0**。这是从空项目开始的独立重写；升级旧实例时，请先备份并验证迁移。具体测试与部署结果见 [执行记录](verification/WORKLOG.md)。

## 先准备模型源

| 模型源 | 你需要准备 | 使用方式 |
| --- | --- | --- |
| ChatGPT 账号 | 可使用 Codex 的账号 | 在网页完成设备码登录 |
| ChatGPT 经企业网关 | Codex 兼容网关地址、OAuth 公共客户端配置 | 先保存网关，再分别完成 ChatGPT 登录与网关授权 |
| Amazon Bedrock Runtime / Mantle | 商业区域、对应的 Bearer API Key、模型权限 | 使用区域固定地址和原生模型目录；不读取个人 AWS profile |
| 国内智谱 Coding Plan | 套餐 API Key、模型 ID | 选择智谱模式；配置原生 Responses 与四类官方 MCP |
| 自定义 OpenAI 兼容服务 | Base URL、模型 ID；服务要求鉴权时再填 Key | 必须支持 **Responses API**，只有 Chat Completions 不够 |

模型目录只能说明客户端知道哪些模型，不能证明账号权限或模型能力。图片、工具、上下文长度和思考档位取决于所选服务。实际对话、压缩和 MCP 会消耗对应服务额度；安装和基础验证不会启动模型回合。

## 安装并访问

服务器仅支持 Ubuntu 24.04 或 Debian 12，支持 x64 / arm64，需要 systemd 与 cgroup v2、Python 3.11+、sudo、e2fsprogs、mount 和 setpriv。Windows / macOS 可作为浏览器客户端或开发机。

取得并检查需要安装的版本源码，进入源码目录后，先打包，再以新的实例名称安装：

```sh
python3 -m deploy.cli pack-source --source . --output /tmp/harness-source.tgz
sudo python3 -m deploy.cli --instance demo install \
  --source /tmp/harness-source.tgz --origin http://127.0.0.1:3300 --port 3300
```

安装器会下载并核验固定运行时、隔离构建应用、创建独立的 gateway、控制、执行和构建账号、生成管理令牌并注册服务。**无需手写 systemd unit、Codex 配置或运行时依赖目录。** 模型源可稍后在网页设置。

网关只监听服务器回环地址。从自己的电脑访问时，保持 SSH 隧道开启：

```sh
ssh -N -L 127.0.0.1:3300:127.0.0.1:3300 用户名@服务器地址
```

浏览器打开 `http://127.0.0.1:3300`，使用服务器上读取的管理令牌登录：

```sh
sudo cat /etc/codex-harness/demo/gateway-token
```

示例中的实例名和端口可以更换，隧道、浏览器地址与安装 origin 必须一致。不要直接暴露网关端口。域名 HTTPS、证书选项和登录入口配置见 [部署指南](deploy/README.md)；DNS、防火墙与公网连通性仍需你自行处理。

## 开始使用

1. 在设置中选择模型源，完成 ChatGPT 登录或填写所需 Key。
2. 添加**服务器上的项目目录**。添加注册不会上传电脑上的项目，也不会修改目录权限。
3. 点击新会话，填写第一条消息并发送。未发送时是本地草稿，正式会话在首发时建立。

会话中可以选择模型、思考档位、审批策略与沙箱，发送附件、批准命令或文件修改、回答补充问题、查看 diff、停止任务和压缩上下文。新会话未覆盖的选项使用项目配置默认值；现有会话未覆盖的选项沿用会话当前设置，包含上次已受理的覆盖，并继续用于后续回合。

## 常用流程

| 想做什么 | 使用入口与行为 |
| --- | --- |
| 计划、追加指令、安排下一条消息 | 输入框选择原生模式，明确追加到当前回合或加入待发队列；会话菜单可修改执行设置、手动请求下一步建议，建议需放入草稿后自行发送 |
| 持续推进目标、查看子 Agent | 会话工具中管理目标和可选预算，查看原生父子任务、状态及结果；定时运行在侧栏“自动化”管理 |
| 查找、分支和导出对话 | 搜索定位原文，从指定回合分支、编辑后重发、导出完整历史；回退对话不会恢复项目文件 |
| 编辑文件与检查代码 | 文件区提供搜索、预览、范围引用、冲突检测编辑、下载和恢复；代码审查有独立启动与停止流程 |
| 提交修改和使用独立工作区 | Git 区核对文件与索引版本后暂存、取消暂存和提交；索引备份、worktree 归档与恢复都有单独入口 |
| 管理工具与上下文 | 设置中管理技能、插件、Apps、MCP、记忆和配置；支持工具表单、资源读取及原生认证入口 |
| 使用终端、远端环境和语音 | 显式打开终端或启动进程，按需登记并选择远端环境；语音需主动开启，并由原生账号和供应商决定是否可用 |
| 检查账户与执行环境 | 模型账户中查看额度、授权与通知；服务管理中运行原生环境诊断或读取内置模型目录 |
| 管理加载状态和云任务 | 侧栏查看已加载会话；云任务入口打开固定版本的官方交互终端，账号需具备对应云服务权限 |

只有终端交互入口的原生功能可通过“原生 Codex 终端”操作，例如 `/hooks`；云任务使用官方 `codex cloud` 界面。两者使用固定版本，与其他执行互斥；退出并确认进程清理后，需要在服务管理中重启原生服务，使配置和账号状态重新同步。

运行能力目录会显示账号、供应商或平台的实际限制。协议中的内部采样、原始历史注入、签名和测试接口不会作为任意 RPC 控制台开放。功能覆盖按工作流程核对，不代表支持上游每个可选参数；详细范围见 [功能清单](FEATURES.md)。

正常关闭网页不会主动取消模型任务。网页终端属于当前连接，断开后会清理，不能用它托管长期服务；终端执行权限也不跟随输入框中的沙箱选项。如果终端清理无法确认，后台会停止当前执行进程，这可能中断其他任务；未确认结果仍需核对，不会自动重发。

断线后会核对原操作编号，**不会自动重发**。显示“结果未知”时，操作可能已执行，应先检查历史和服务状态。停止请求被接收也不等于任务已经结束。长历史、工具内容和附件有容量上限；未加载完或超出容量时会明确提示。

设备授权码只对发起登录的当前连接开放，断线或取消后撤销；操作记录不保存授权码。图片与音频按需加载，外部媒体只提供明确的打开链接。额度重置和通知工作区所有者的邮件都需要单独确认，不会自动执行。

## 日常管理

网页设置提供账号、MCP、模型源、目录同步与服务状态入口。变更配置前需结束任务和终端；状态未知时先恢复后台，不能通过反复点击开始新操作。

从经过检查的部署工具目录执行：

```sh
sudo python3 -m deploy.cli --instance demo status
sudo python3 -m deploy.cli --instance demo verify
sudo python3 -m deploy.cli --instance demo logs --service worker --lines 100
sudo python3 -m deploy.cli --instance demo restart
sudo python3 -m deploy.cli --instance demo update --source /tmp/next-source.tgz
sudo python3 -m deploy.cli --instance demo rollback
```

更新先准备、隔离构建并校验新版本，再确认服务停止后切换。切换或恢复无法确认时保留恢复材料并报错。不要在运行目录直接 `git pull`，也不要单独升级 Codex CLI。应用与可信管理工具分别更新，具体修复重装和恢复步骤见 [部署指南](deploy/README.md)。

本次重写使用新部署结构。旧数据不会被安装器自动覆盖或删除；迁移前先备份并验证新实例。卸载默认保留数据、密钥和恢复记录，不等于清空凭据。

## 开发与检查

需要 Node 24 LTS（24.15+）、pnpm 11.22.0。不要用个人 Codex 配置做测试。

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm typecheck
pnpm build
pnpm test:targeted tests/core/ledger.test.ts tests/gateway/http.test.ts
```

修改后只运行受影响的定向测试。完整审计覆盖所有模块；连续三轮没有新增问题后，`pnpm test:full` 才会放行。跳过项和外部供应商未验收项不会计为通过。实际 Linux 权限、systemd、HTTPS 和外部模型测试的边界记录在验证文档中。

设计边界见 [架构](ARCHITECTURE.md)，过去问题对应的新验收条件见 [问题清单](PROBLEM-ACCEPTANCE.md)。协议由官方固定 CLI 独立生成，来源见 [记录](reference/PROVENANCE.json)。

## 权限与数据

管理登录、HTTPS 入口登录和模型账号登录是三个不同环节。worker 不持有网页管理令牌，也没有系统管理权限；项目列表只是目录选择，并非沙箱边界。模型和 MCP 会向相应服务发送执行任务所需的内容。

站点访问认证过期时，保留当前页面，按提示在新标签页完成认证，再回到原页点击“重新检查登录”。草稿会保留，之前的写入请求不会自动重发。

配置、会话与恢复备份可能包含敏感信息，不要提交到 Git。管理令牌不要交给会话中的 Agent。首次安装检查通过不代表真实供应商、公网证书或第三方认证已完成业务验收。
